## Existing key handling without sharing secrets

When the correct Windows account has valid application credentials, open Picard > Tools > NEOWULF > Quellen-Zugangsdaten (Windows DPAPI). Fields support Spotify Client ID/Secret, SoundCloud ID/Secret or existing OAuth tokens and Last.fm API key. Values remain DPAPI-encrypted in the local user profile, not in GitHub, Picard.ini or chat. Configure provider enablement under Tools > PicardWulf > Anbieter, Suchumfang und Anfragebudget. If a source is RESTRICTED or CREDENTIALS_REQUIRED, its results cannot be treated as an empty match.

Credentials cannot be self-issued without signing in to the relevant developer account, and this does not authorize paid Artist Pro/Premium purchases. Do not invent keys, ask for passwords in chat, or reuse another application's client secret.

## Why adding files previously did not trigger searches

An earlier code revision auto-paused all provider dispatch on restart when backlog exceeded 2,000 entries. v1.0 now **reports the large backlog instead of automatically pausing**; an explicit persisted pause is still honored. Provider calls are still rate-limited, disk scheduling is bounded, and API quotas can defer queries, so an enabled provider may legitimately be WAITING_QUOTA rather than failing.

Current public adapter enrichment on a strongly matched Deezer track uses one bounded track detail lookup and one album lookup, both charged to the common Deezer provider budget. It does not infer facts from other album editions. Conflicting details forbid automatic scoring and tag application. Existing albumartist values and manually entered genre/label/date/track positions have safeguards; new metadata appears in Picard memory by default. Full automatic saving remains disabled.

## Safe rollout and unverified gates

1. Verify BMAX Picard.exe session, plugin hash, pause status and queue using the correct authorized Windows account. SSH passwordless authentication from Legion to BMAX failed in read-only attempts; GUI status is not observed.
2. Keep Picard running. If UI responds, disable **only PicardWulf** in Options > Plugins before using the verified live installer, then re-enable. Do not change plugin binaries while enabled.
3. In Tools > NEOWULF > Quellenstatus und Warteschlange verify sources, pause, backlog. If explicitly paused, resume only when intended. Review returned candidates through Tools > NEOWULF > Gesammelte Treffer ansehen.
4. Use small disposable audio copies for Save-with-Backup, confirmation, rename/move and restore checks before trusting large imports.
5. On the actual BMAX Windows Picard 3 build, validate 29k known + 10k new files, UI event-loop latency, provider quotas, exact release selection and no false Various Artists/Apple Music credits.
6. Do not label v1.0 production-ready until actual on-host credentials, provider responses, Picard plugin activation and async save/restore have been verified.

**Current limit:** The user still needs eligible developer-account approval for SoundCloud/Spotify and a Last.fm developer account if none exists. The running Windows plugin has not been changed by development work on Legion.
