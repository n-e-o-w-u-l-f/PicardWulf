# PicardWulf v1.0 — Next Execution Plan, Risk Gates and Acceptance

**Prepared:** 2026-10-14
**Version target:** **v1.0** ONLY. No v1.0.1 / 1.1 milestone is to be implied by intermediate commits.
**Research basis:** [Deep architecture review](../research/PICARDWULF-V1.0-DEEP-RESEARCH-2026-10-14.md).
**Delivery discipline:** Research → plan → implementation → tests → review → GitHub push → controlled Picard plugin deployment → actual BMAX runtime evidence. These are distinct states.

## 0. Scope lock: complete product target

**Source discovery:** MusicBrainz, Deezer, Apple/iTunes, Spotify, SoundCloud, Last.fm through one common adapter manager with capability, authentication, terms, cache and quota. Providers not usable without paid accounts remain optional/disabled and never block healthy sources. Extend through a controlled adapter interface rather than promises to scrape arbitrary websites.

**Workflow:** Add Folder should consider all **eligible available** providers, select the objectively highest-scoring **release** rather than the first MusicBrainz recording, preserve provider name/IDs as provenance, and avoid applying ambiguous editions. The actual winner is updated in Picard's unsaved preview by default; optional tag persistence is backed up and verified.

**Native integration:** Keep Picard's normal MusicBrainz release/recording workflow for authentic MBIDs; external catalog releases remain in PicardWulf's own album/release view. Provider-specific sources cannot be faked into MusicBrainz entity IDs.

**NEOWULF:** Preserve prior advanced custom naming scripts, profile validation, series/discs/compilations rules, safe fallback and the Eminem *Curtain Call 2* fix; test actual exported scripts before release. Provider name must never become `albumartist`.

**Reliability:** Handle at least **29,000 known + 10,000 newly imported files** without freezing Picard, deleting DB state, requiring restart, paying new services or losing unpersisted user changes.

## 1. FIRST NEXT STEP (execute in this exact order)

### S0: Observe & freeze runtime facts (no Picard shutdown)
- Confirm GitHub main HEAD, local clean worktree, current plugin manifest/config schema and executable permissions.
- Record BMAX Picard PID, GUI heartbeat responsiveness, 29k/10k actual counters, user `megal`, installed plugin hash, enabled state, and read-only queue database `PRAGMA quick_check`, counts by state, DB/WAL sizes and timestamps **only where authorized runtime tooling is already available**. Do not cause login/policy bypass if no safe authorized session.
- If Picard GUI responds, pause metadata searches or disable only **the plugin**, not Picard. Preserve loaded tracks and unsaved changes. If GUI unresponsive, gather non-destructive CPU/RAM/wait-chain diagnostics; no attempted GUI automation that might force termination.
- Capture baseline resource metrics while idle and under controlled *small* load; only publish aggregate diagnostics (no credentials or private song path).
- Make a versioned, verified **consistent SQLite backup using SQLite's backup API**, not a raw live-file copy and **never** delete live `-wal/-shm`.
- If any precondition fails: leave Picard open, mark `BLOCKED_RUNTIME` with exact reason, continue code/research on Legion. No cosmetic retry of a platform-denied login.

**Exit gate S0:** Observed vs inferred facts clearly separated, backup/recovery path present and current session unchanged. If BMAX unavailable, S0 remains OPEN; do not claim deployment.

### S1: Stabilize the ingest and SQLite scheduler (P0)
- Separate GUI snapshot ingestion, durable committed queue, provider dispatcher and result delivery using Qt queued signals and one dedicated DB writer.
- Replace unbounded in-memory `_ingest` with fixed capacity (initial guard: 2,048 entries) and visible backpressure. Never drop jobs; only confirm 'persisted' after commit. On DB failure, pause safely and show staged/persisted distinction.
- Remove `get_results()`, database connection attempts and full-media backup/hash from QTimer callbacks/UI actions. Use immutable message envelopes for workers and versioned file identity references for GUI callbacks.
- Use per-provider task states, persistent resume cursor, dedupe, WAL only for local disks, bounded transactions, fail-safe schema migration and integrity checks. Limit DB busy time strictly off-GUI. Configurable batch size and adaptive pacing, not unlimited concurrency.
- Give newly added files fair processing relative to historical 29k backlog; never rescan unchanged already known files unless explicitly requested.
- Add pause/resume, stop-flush acknowledgement, queued/committed/running/retry counts, provider-specific ETA based only on observed rate, and cancellation of obsolete work.
- Validate concurrent plugin disable/enable and clean shutdown vs simulated abrupt termination; treat memory-only work as **not yet durable**, never misreport it as durable.

**Exit gate S1:** No SQLite/media I/O on GUI thread; load-test 39k identities including 10k new; no lost **committed** jobs after restart; bounded RAM and bounded GUI event latency. Proposed thresholds on a representative BMAX test: p95 GUI event-loop lag <100 ms, p99 <250 ms and no stalls above 1 s due to plugin calls. Thresholds are targets requiring runtime measurement, not present results.

### S2: API compliance & adaptive query planner (P0/P1)
- Implement provider capability discovery with `AVAILABLE`, `CREDENTIALS_REQUIRED`, `QUOTA_WAIT`, `TEMPORARY_ERROR`, `RESTRICTED`, `DISABLED`; no empty result should masquerade as success.
- Local-first: inspect existing MBIDs/ISRC, file identity and album folder; cache known songs/releases; select provider queries **on demand**. Strong local matches need not fan out to all services unless the user explicitly asks 'exhaustive mode'.
- Apply provider-wide rate budgets, token buckets persisted across plugin reloads, 429 Retry-After, 503 and 401 invalid-credential handling, jittered limited retries, circuit breaker and bounded response size.
- Implement **Spotify 2026** auth and quota capability check; never assume free Premium access; do not create or subscribe to paid accounts.
- Implement **SoundCloud 2026** OAuth2.1 with legitimate app credentials/token refresh, one-time refresh token rotation and secret-safe failures. No support for credentials or registrations not available to user.
- Test Deezer public search independently from developer app registration and respect its metadata-use rights (including **no album image cache**).
- Use album-local normalized candidate cache, optional Last.fm enrichment only when value adds to matching, and avoid repeating 10k duplicate album queries.
- Provider request budget is operator-adjustable; provide clear status why a provider was skipped.

**Exit gate S2:** Every provider has a capability, policy, auth/quota and parser test; tests with 401/403/429/503/network-loss pass, and no forced paid dependency. For live validation, show actual response or `UNAVAILABLE`, not guessed success.

### S3: Source-neutral release/edition ranking (P0/P1)
- Separate recording identity (ISRC, recording MBID, AcoustID) from **release edition** (album title/artist, tracklist, track number/total, year, region, barcode, edition, source album ID). Do not use recording ID to invent a release MBID.
- Normalize transliteration, featuring credits, punctuation and release suffixes without hiding live/remix/clean/remaster distinctions.
- Build album-cluster consensus from multiple tracks; no same-song-on-greatest-hits false merger.
- Return `COMPLETE`, `INCOMPLETE`, `AMBIGUOUS`, `SAFE_WINNER` with reason codes and full sorted alternatives. Keep a fixed decision once applied; later conflicting results reopen review rather than overwrite again.
- Score is **not** a statistical 93.5% probability until calibrated. Label 'matching points' with versioned weight breakdown and abstention threshold.
- Create ground-truth corpus with Eminem Curtain Call 2, VA vs solo compilations, multilingual names, single vs album, 2-disc editions, wrongly preexisting MBIDs, absent tags, Spotify/Deezer higher-scoring winners.
- Track confusion matrix, false-positive release selection, wrong albumartist, manual-review ratio and robust abstention.

**Exit gate S3:** On curated corpus **zero incorrect automatic writes/assignments** and zero provider-name artist corruption; no high-confidence wrong edition. Any unresolved case abstains. Calibration changes require test evidence and versioned weights.

### S4: Metadata write, backup and rollback (P0)
- Default **PREVIEW only**. Writing requires user-controlled enablement, specific source/field policy and evidence of an unambiguous release.
- Make full-media backup/hashing off UI with disk-space preflight, verify original hash/mtime/size before Picard save, immutable journal, and backup retention outside imported folders.
- Qt thread schedules Picard `File.save()` only after backup acknowledged. Associate save correlation ID with post-save hook, detect async failure or path rename/move, verify resulting file tags and preserve restoration source.
- Recovery must be explicit, dry-run first, never automatically overwrite another changed file or delete backup. Write failures leave original backup and a visible status.
- Protect existing tags, user-manual edits, active naming profile and albumartist/artist source trust boundaries.
- Add a source-to-field provenance report; keep provider credentials out of metadata and logs.

**Exit gate S4:** For real disposable copies of MP3/FLAC/OGG/M4A, validate before/after tags, rename/move rules, backup equality, write-error paths, restore and duplicate writes. Zero irreversible operations on originals.

### S5: Installer, operator UI, documentation and v1.0 release gate
- Runtime detector verifies Picard 3 API, plugin UUID, active account, plugin enabled/disabled state before atomic hot-reload; otherwise fail safely without restart or changing files. Preserve local edits.
- Ensure settings persistence across profiles, credential upgrades, schema migration rollback, and disabled-provider privacy choices.
- Export read-only diagnostics: GUI event loop liveness, memory, scheduler state, provider quotas, last errors, score rationale; no credentials/music filenames in published exports.
- Keep eleven README translations cross-linked and aligned with actual toggles and capabilities; write migration, support, rollback and verification instructions.
- Run on Legion's existing local runner only, no new charged CI. Verify GitHub push by readback; Windows/BMAX runtime remains a separate acceptance gate.
- **Only when S0–S5 are passed with actual BMAX evidence**, publish stable release/tag **v1.0**. Do not release a v1.0.1 or claim 1.0 completed because local mocks passed.

## 2. Minimal tests and adversarial scenarios

| Suite | Required cases | Acceptance |
| --- | --- | --- |
| Qt responsiveness | 39k known + 10k new + plugin enabled; UI selects tracks while processing | p95 <100ms; p99 <250ms measured on BMAX; no plugin-caused UI stall |
| Durable queue | clean plugin disable, crash between stage/commit, power-stop simulation, DB SQLITE_BUSY, full disk, schema v1 migration | All **committed** jobs resume exactly once logically; undurable state never claimed committed; no DB deletion |
| Provider failure | 401/403, 429 Retry-After, 503, timeout, invalid JSON, source unavailable, expired OAuth, canceled album | No stall, no unbounded retry, state accurately categorized |
| Ranking | same recording multiple albums, artist comps vs VA, duplicates, covers/remixes, wrong MBID, multilingual, missing tags, mixed albums | Zero false automatic commits in curated high-risk corpus; ambiguous records wait for review |
| Saving | backup disk failure, original edited during backup, save exceptions, asynchronous failure, rename/move and successful write, restore | No write without verified backup; post-save state verified; original restorable |
| Deployment | unknown modified previous plugin, enabled plugin during update, incomplete package, interrupted copy, no Windows auth, API mismatch | Abort without Picard stop, retain previous good plugin and data |
| Privacy & license | secret in logs/cache, service quota limit, Deezer image caching, unauthorized paid integration | Zero secret leaks; no prohibited cached assets; no new charged service |
| Metadata integrity | Eminem *Curtain Call 2*, artist vs albumartist, compiler naming, series/disc/fallback scripts | No 'Various Artists' or 'Apple Music' false credit; original NEOWULF naming preserved |

## 3. Work ownership, dependency and completion rule

**Next implementable code step:** S1 only (scheduler/GUI I/O), in a focused Git commit and test suite. No parallel API/ranking refactor until S1 is stable. Then S2→S3→S4→S5 in dependency order. All changes within **PicardWulf v1.0**.

**Failure governance:** Before retry, record operation+target+mechanism+environment+acceptance fingerprint; classify `CONTROL_SUFFICIENT_AND_FOLLOWED`, `CONTROL_SUFFICIENT_BUT_IGNORED`, `GUARD_OR_CHECKER_DEFECTIVE`, `GOVERNANCE_GAP`, `EXTERNAL_BOUNDARY`. Never repeat equivalent failed mechanism without new evidence. Keep last good commit and backed-up plugin.

**Safe state for next turn:** GitHub code unchanged by this *research* except documents/version wording; Picard on BMAX **not touched**. No API calls against personal music, no media writes, no paid services.

**DoD — full v1.0:** user can add a large folder, all eligible providers are considered under documented quotas, high-confidence best release (not automatic MusicBrainz priority) appears with correct albumartist/provenance, safe opt-in tags are backed up and verified on BMAX, NEOWULF naming rules work, and Picard stays responsive and open. No stable-release claim before all gates.
