# PicardWulf v1.0 — S5 multi-source context-menu corrections

Date: 2026-10-15. Development source checkpoint, NOT a BMAX Windows runtime release.

## What failed in the previous context-menu implementation

1. An actual provider album/release ID appeared in several tracks, yet search-only candidates often lack release_date, barcode, totaltracks or albumartist; other tracks from the SAME release had enriched values. The old composite release key included these optional fields and **fragmented one official album** into two or more groups. In a four-track fixture, only three tracks were counted. This could suppress correct 75%-coverage suggestions when the missing data was widespread.
2. A 200-track album invoked edition_conflicts 20,100 times because every candidate was compared with every earlier track. This happened inside a Qt-timer callback and could harm GUI responsiveness on larger groups.
3. The follow-up detail dialog did not select the release/track the user clicked in the ranked album results, forcing the user to search again among all candidates.

## Changes

- Group provider releases by their actual provider-namespaced release ID and album/version title. **Missing optional metadata does not create a new release**. If two present attributes contradict (e.g. different release months, country, barcode or albumartist) the affected album proposal is withheld, not silently unified. Different release IDs are NEVER merged.
- For candidates with NO authentic source release ID retain conservative title/albumartist/edition constraints. Do not invent IDs.
- Replace quadratic pairwise conflict checks with a single accumulating evidence snapshot per release. Track/disc positions are intentionally excluded (they differ for songs); later, more precise compatible dates replace abbreviated dates. The synthetic 200-track regression asserts <=650 comparisons.
- Pass the selected provider + exact album ID + artist/title/album track to the follow-up detail view and highlight the same row. No automatic saving or fabricated MusicBrainz IDs.
